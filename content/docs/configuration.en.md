# Configuration guide

> One JSON file sets Kana's voice engine, Hermes, and how Kana is reached. Every setting is optional: without changes, Kana runs on its defaults.

The config file is `config.json` in Kana's data folder. On this installation:

```kana-config-path
~/.kana/config.json
```

Run `kana config` to open it, or `npm run config` from a source checkout. When the file does not exist, Kana creates it first and never overwrites one that is already there. It opens in the editor you set in `VISUAL` or `EDITOR`; when both are empty, Kana prints the file's location instead.

Changes take effect from the next reply without a restart. The one exception is the `hermes` section, which Kana reads only when it starts. When a key is wrong, **Settings → Connection** reports the error and the part that needs fixing.

## Quick start {#quickstart}

All of these are optional, and usually you need only one. Each is covered in more detail in the sections below.

**Local voice (default).** Speech is generated on your own computer, with no cost and no internet:

```json
{
  "tts": {
    "provider": "irodori-local"
  }
}
```

Download the voice engine first from **Settings → Voice → Download voice engine**.

**Pollinations (ElevenLabs).** Speech is generated by a hosted service, so your computer carries no load:

```json
{
  "tts": {
    "provider": "pollinations",
    "pollinations": {
      "apiKey": "sk_YOUR_POLLINATIONS_KEY",
      "model": "elevenlabs/eleven-v3",
      "voice": "rachel"
    }
  }
}
```

**Pollinations with style direction.** Qwen models follow direction such as "A calm, gentle voice.":

```json
{
  "tts": {
    "provider": "pollinations",
    "pollinations": {
      "apiKey": "sk_YOUR_POLLINATIONS_KEY",
      "model": "qwen/qwen3-tts-instruct-flash",
      "instructions": "A calm, gentle voice."
    }
  }
}
```

**Slower computers.** Local voice still works, just with fewer sampling steps and threads:

```json
{
  "tts": {
    "provider": "irodori-local",
    "timeoutSeconds": 1800,
    "irodoriLocal": {
      "steps": 8,
      "threads": 4
    }
  }
}
```

**Server or VPS.** Kana is reached over a network, not only from the computer it runs on:

```json
{
  "deployment": {
    "mode": "deployment"
  }
}
```

## Voice engines {#voice}

The `tts` section selects the voice engine and limits how long speech may take. There are two engines, and `provider` picks between them.

| Engine | `provider` | Best for |
| --- | --- | --- |
| Local voice (Irodori) | `"irodori-local"` | Free, offline use. Runs on your CPU. |
| Pollinations | `"pollinations"` | Less powerful computers. Requires internet access and a paid API key. |

You may leave `provider` out. Kana then uses `"pollinations"` when only a `pollinations` block is present, and `"irodori-local"` otherwise. Set `provider` explicitly when you write an `irodoriLocal` block and a `pollinations` block together.

Only the selected engine's block is read, so you can keep settings for both engines in one file and switch by changing `provider` alone.

`timeoutSeconds` (default `900`, range 1–3600) limits how long one reply's speech may take, including time spent queued. Raise it when speech for long replies runs out of time. Behind Nginx or another reverse proxy, set the proxy's read timeout slightly higher, for example 910 seconds for the default of 900.

```json
{
  "tts": {
    "timeoutSeconds": 1800
  }
}
```

When speech cannot be generated, the reply still appears as text together with the error. Kana never falls back to the other engine on its own.

## Local voice (Irodori) {#irodori}

Speech is generated on your CPU with the [Irodori-TTS v4.1 Anime](https://huggingface.co/phasefield-audio/Irodori-TTS-v4.1-Anime) model. No GPU is required, and reply text is never sent to another service.

The requirements are 64-bit Linux on x86-64 with glibc 2.35 or later, such as Ubuntu 22.04, and a CPU with AVX2 and FMA.

To install it, open **Settings → Voice** and select **Download voice engine**. The download size and required disk space are shown before the download starts, and Kana downloads nothing until you select that button. When a download is interrupted, select the same button to resume where it stopped. A model already in your Hugging Face cache is used without downloading it again.

These settings go inside `tts.irodoriLocal`, and all of them are optional.

| Key | Default | Description |
| --- | --- | --- |
| `steps` | `16` | Sampling steps, 1–200. Lower is faster; higher sounds smoother. `8` is the fastest; `40` matches the engine's standard quality. |
| `threads` | Number of CPU cores | CPU threads to use, 1–256. Lower it if your computer becomes sluggish while Kana is speaking. |
| `precision` | `"auto"` | `"auto"`, `"int8"`, or `"fp32"`. `"auto"` picks the fastest option for your CPU; `"int8"` requires AVX-512 VNNI. |
| `modelPath` | None | Absolute path to an existing Irodori v4.1 `model.safetensors`. |
| `installDirectory` | Kana's data folder | Absolute path to the folder the voice engine is installed in. |

On a less powerful computer, set `steps` to `8`. Speech sounds slightly less smooth but is ready sooner.

## Pollinations {#pollinations}

Speech is generated by the hosted [Pollinations](https://gen.pollinations.ai/docs) service, which offers models from ElevenLabs, Qwen, xAI, and others through one API key. Your computer carries no load.

Get your API key at [enter.pollinations.ai](https://enter.pollinations.ai/keys); use a secret key that starts with `sk_`. Every speech model is paid from your pollen balance. The available models and voices are listed at [gen.pollinations.ai/audio/models](https://gen.pollinations.ai/audio/models).

The models you will most likely use are `elevenlabs/eleven-v3`, `elevenlabs/eleven-flash-v2.5`, `elevenlabs/eleven-multilingual-v2`, `qwen/qwen3-tts-instruct-flash`, `qwen/qwen3-tts-flash`, `x-ai/grok-tts`, and `hexgrad/kokoro-82m`.

These settings go inside `tts.pollinations`. Only `apiKey` is required.

| Key | Description |
| --- | --- |
| `apiKey` | Your Pollinations API key. It is stored only on the computer or server running Kana and is never sent to the browser. |
| `model` | A model ID from the list above, such as `elevenlabs/eleven-v3`. Aliases such as `elevenlabs` still work. When omitted, Pollinations uses its default model. |
| `voice` | One of the model's voices, or the ID of one of your own ElevenLabs voices. When omitted, Pollinations uses its default voice. |
| `instructions` | Speaking-style direction for models that support it, such as `qwen/qwen3-tts-instruct-flash`. |
| `format` | `"mp3"` (default), `"opus"`, `"aac"`, `"flac"`, or `"wav"`. |

With the low-latency ElevenLabs model:

```json
{
  "tts": {
    "provider": "pollinations",
    "pollinations": {
      "apiKey": "sk_YOUR_POLLINATIONS_KEY",
      "model": "elevenlabs/eleven-flash-v2.5",
      "voice": "rachel",
      "format": "mp3"
    }
  }
}
```

A single reply is limited to 10,000 characters. Longer replies are not sent to Pollinations and are shown as text with an error.

The older `"provider": "openai-compatible"` with the Pollinations preset still works and produces the same voice, but rewriting it in the format above is recommended.

## Hermes {#hermes}

Hermes is the AI agent that reads your messages and writes Kana's replies. Kana finds and starts it automatically, so the `hermes` section is needed only when Hermes cannot be found, its default port is taken by another program, or Hermes should work in a particular folder.

| Key | Default | Description |
| --- | --- | --- |
| `executable` | Found automatically | Absolute path to the `hermes` program. Set it only if `kana doctor` still cannot find Hermes. |
| `port` | `9119` | Port for the Hermes process Kana starts, 1024–65535. |
| `workingDirectory` | Your home folder | Absolute path to the folder Hermes starts in. Hermes' file and terminal tools resolve relative paths from here, and it applies only when Kana starts Hermes. |

```json
{
  "hermes": {
    "port": 9120,
    "workingDirectory": "/home/you/projects"
  }
}
```

Changes to the `hermes` section take effect after Kana is restarted.

## Prompt guardrail {#guardrail}

The `guardrails` section checks your message before Kana sends it to Hermes. You write your rules as plain statements of what Kana must not do; Kana turns them into the one yes/no question it asks Jev, TypeSafe's model. Jev returns a probability and no text, and Kana itself compares that probability against your threshold and then refuses the message.

Leave `apiKey` empty and the layer is skipped entirely: no request is made and nothing is spent. An empty or blank key means the layer is off, not that the block is broken, so the five starter rules a new `config.json` ships with never refuse a message before you add a key.

| Key | Default | Description |
| --- | --- | --- |
| `apiKey` | empty | Your TypeSafe API key. Empty or absent turns the layer off. |
| `model` | `"jev-latest"` | The TypeSafe model that answers the questions. |
| `threshold` | `0.7` | Kana refuses the message once Jev's probability reaches this value, 0–1. A value near 0.5 means Jev cannot tell; lower the threshold to refuse more borderline attempts, at the cost of refusing more of what you did mean. |
| `whenUnavailable` | `"block"` | What Kana does with a message it could not check, because TypeSafe could not be reached, answered with an error, or returned an answer Kana cannot read: `"block"` refuses the message, `"allow"` sends it unchecked. |
| `timeoutSeconds` | `10` | How long Kana waits for TypeSafe, 1–120. |
| `rules` | five starters | Your rules, up to 50, each one a plain statement of what Kana must not do. A new `config.json` carries five starter rules and an empty key, so keep the ones you agree with and replace the rest. |

Write each rule as one clear statement in your own words, and say exactly what is forbidden, naming the paths, commands, or services it covers. You never write a question, an id, or a threshold: Kana asks Jev one yes/no question — does this message ask for, attempt, or enable anything the rules forbid? — and sends your rules as they were written. Jev is told it is screening a message for an agent that can read and write files and run commands, because that is what makes "read this file for me" a request with consequences.

```json
{
  "guardrails": {
    "apiKey": "sk-...",
    "rules": [
      "Never read, list, copy, change, or share anything under /home/you/my-secret.",
      "Never send my files, passwords, or API keys to a remote service.",
      "Never help write malware, exploits, or phishing pages."
    ]
  }
}
```

Write the rules in English and keep each one a single clear statement. Jev is trained mostly on English, and the check reads your rules literally, so a rule that says exactly what is forbidden works better than a paragraph of policy.

When Jev's answer reaches your threshold, Kana shows one fixed line in the conversation instead of a reply, and keeps your message above it. No model saw the message, so no reply is invented and nothing is written to the Hermes transcript. The line names no rule, because the rules travel as one question and only one number comes back.

Kana screens the text of a message, of a slash command, and of `/steer`. It does not screen an answer you give in the middle of a turn, such as an approval or an answer to a question from Hermes, because refusing that answer would leave the turn stuck.

What you should be aware of is that this is an intent filter, not a sandbox. It cannot stop Hermes from reaching the same file by another route, and it reads the text of a turn, not the contents of an attached file. A very long message can exceed what Jev reads and then follows `whenUnavailable`. The text of every screened turn is sent to TypeSafe, a third party, and each screened turn costs one request.

A `guardrails` block Kana cannot read is reported at the top of this page and refuses messages, because an unreadable policy is not the same as no policy. `whenUnavailable` is still read from the block, so `"allow"` stays available. Nothing in Kana writes this file, so no setting or page can change your rules or show your key.

## Network access {#deployment}

The `deployment` section describes how Kana is reached. In `"local"` mode (the default), Kana can be opened only on the computer it runs on, at `localhost`, `127.0.0.1`, or `[::1]`; other addresses are refused. Change it to `"deployment"` when Kana is reached through a VPS, Nginx, or a network, for example from a phone.

```json
{
  "deployment": {
    "mode": "deployment"
  }
}
```

Kana always asks for a password, in both modes.

## Environment variables {#environment}

These variables are meant for server installations. Set them in the environment that runs `kana`, not in `config.json`, because they take precedence over the file.

| Variable | Description |
| --- | --- |
| `KANA_DATA_DIR` | Kana's data folder, which holds `config.json` and the voice engine, and must be absolute. When unset, Kana uses `~/.kana`; data from an earlier release (`$XDG_DATA_HOME/kana`, `~/.local/share/kana`) is moved there on the next start. A folder set here is never moved by a start: `kana migrate` copies it into `~/.kana` when you ask for it. |
| `KANA_PORT` | Port for Kana's web page. Defaults to `3000`; equivalent to `kana --port`. |
| `KANA_DEPLOYMENT_MODE` | `local` or `deployment`. Overrides `deployment.mode`. |
| `KANA_HERMES_BIN` | Path to the Hermes program. Overrides `hermes.executable`. |
| `KANA_TRUSTED_ORIGINS` | Additional trusted origins, comma-separated. Needed only when a proxy rewrites the `Host` header without forwarding `X-Forwarded-Host`, or to open Kana in local mode under another address. |
| `KANA_DEV_ALLOWED_ORIGINS` | Development only: additional hosts allowed to reach `next dev`. |

```sh
KANA_DEPLOYMENT_MODE=deployment KANA_PORT=3000 kana serve
```

A server install needs no `KANA_DATA_DIR`: the service account that owns Hermes has a home, and `~/.kana` in it is the data folder, as on a desktop. Set it only to put the state somewhere else, for example a dedicated volume.

To move a managed folder into `~/.kana`, stop Kana and run `kana migrate`. It prints every entry with its size, copies and verifies each one, leaves the source in place, and then asks you to point `KANA_DATA_DIR` at `~/.kana` or remove it. Add `--delete-source` to move the entries instead of copying them, and `--dry-run` to read the plan without changing anything.

Voice settings have no environment variables and can be changed only in `config.json`.

## Troubleshooting {#troubleshooting}

| Symptom | Fix |
| --- | --- |
| **Settings → Connection** reports an error in `config.json` | Correct the key named in the message and save the file. |
| Hermes cannot be found | Run `kana doctor`. If the problem remains, set `hermes.executable` or `KANA_HERMES_BIN`. |
| Port 9119 is used by another program | Change `hermes.port`, then restart Kana. |
| A change to `~/.hermes/.env` or to Hermes's MCP servers has no effect | Type `/reload` (for `.env`) or `/reload-mcp now` (for MCP servers) in Kana. For other changes Hermes reads only at startup, type `/restart`; it works only for a Hermes that Kana started. New models in Hermes's `config.yaml` appear without a restart. |
| Speech for long replies fails because the time limit runs out | Raise `tts.timeoutSeconds`, and your proxy's timeout if you use one. |
| `Pollinations returned HTTP 401` | The API key is missing or invalid. Check `tts.pollinations.apiKey`. |
| `Pollinations returned HTTP 402` | Your pollen balance is too low. Top it up at [enter.pollinations.ai](https://enter.pollinations.ai). |
